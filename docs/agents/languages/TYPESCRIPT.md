# TypeScript Rules

## 适用场景

- 修改 `.ts`、`.tsx`、`.mts`、`.cts` 或 TypeScript 编译配置

## 必须

- 遵循现有 `tsconfig`、模块系统、运行时和包管理器
- 在使用前收窄 `unknown` 和外部输入，不用 `any` 绕过类型错误
- 区分编译期类型与运行时数据验证
- 保持公开类型和 API 兼容，除非任务明确要求破坏性修改

## 建议

- 优先复用项目已有类型，并让类型靠近其使用位置
- 使用可辨识联合表达有限状态
- 让异步错误和取消行为显式可追踪

## 避免

- 无依据的类型断言、非空断言和过度泛型
- 为一次性对象创建大规模类型层级
- 同时维护无必要的重复类型定义

## 验证

- 运行项目现有 typecheck、lint 和相关测试命令
