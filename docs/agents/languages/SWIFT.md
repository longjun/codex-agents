# Swift Rules

## 适用场景

- 修改 Swift 源码、Swift Package 配置或 Swift 编译行为

## 必须

- 遵循项目现有 Swift 版本、并发模型和 API 可用性范围
- 明确处理可选值、错误和任务取消，不用强制解包掩盖不确定性
- UI 状态更新遵守项目现有的 actor 隔离规则
- 保持公开 API 兼容，除非任务明确要求破坏性修改

## 建议

- 优先使用值类型和标准库能力
- 用小型协议表达真实边界，不为测试或潜在复用提前抽象
- 让异步任务的所有权、生命周期和取消路径清晰

## 避免

- 无依据使用 `!`、`try!`、`as!`
- 无边界的 detached task、共享可变状态或隐式线程切换
- 仅为模仿其他语言而引入额外分层

## 验证

- 使用项目现有方式执行构建和相关测试
- 对并发或生命周期修改检查取消、释放和主线程更新路径
