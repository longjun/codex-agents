# Go Rules

## 适用场景

- 修改 Go 源码、模块配置或 Go 构建行为

## 必须

- 使用 `gofmt`，遵循现有 Go 版本和模块边界
- 错误必须被处理或有意返回；包装错误时保留可检查的原因
- `context.Context` 由调用链传递，不存入结构体或用空 context 替代已有 context
- goroutine 必须有明确的退出、取消和错误处理路径

## 建议

- 接口保持小型，并优先由使用方定义
- 优先返回具体类型，仅在真实边界处引入接口
- package 命名简短清晰，避免无意义的 `util`、`common` 或 `base`
- 复用标准库和项目现有实现

## 避免

- 为每个实现创建一一对应接口
- `panic` 处理可恢复的业务错误
- 隐式 goroutine 泄漏、无界并发和共享可变全局状态

## 验证

- 运行 `gofmt`、相关 package 测试和项目既有静态检查
