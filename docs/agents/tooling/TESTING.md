# Testing Rules

## 适用场景

- 新增或修改测试、测试基础设施、fixture、mock 或测试配置

## 必须

- 测试验证可观察行为，不复制实现细节
- 每个测试独立、可重复，并清理创建的外部状态
- 修复缺陷时优先添加能重现原问题的最小回归测试
- 异步测试必须等待真实完成条件，不依赖任意 sleep
- 不通过降低断言强度、跳过测试或扩大重试掩盖失败

## 建议

- 先运行最聚焦的测试，再运行受影响范围的完整检查
- 优先使用真实轻量依赖；只在边界清晰且必要时 mock
- fixture 保持最小，并让失败信息直接指向行为差异

## 避免

- 测试私有函数、内部调用次数或无意义快照
- 跨测试共享可变状态
- 为简单行为构建复杂测试框架

## 验证

- 至少证明新测试在修复前失败、修复后通过，或说明无法执行该验证的原因
