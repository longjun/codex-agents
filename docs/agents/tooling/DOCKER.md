# Docker Rules

## 适用场景

- 修改 Dockerfile、Compose、镜像构建或容器运行配置

## 必须

- 固定关键基础镜像版本，并遵循项目现有更新策略
- 使用多阶段构建或等价方式避免将构建依赖和敏感文件带入运行镜像
- 容器默认使用非 root 用户，除非有明确且受控的理由
- secret 通过安全注入提供，不写入镜像层、构建参数或仓库文件
- `.dockerignore` 排除无关上下文、凭证和本地产物

## 建议

- 保持镜像层和构建步骤简单、可缓存、可调试
- 让运行配置、健康检查、端口和持久化目录明确
- 应用正确处理终止信号，并以前台进程运行

## 避免

- 使用无版本约束的 `latest`
- 在单层 shell 命令中堆积难以诊断的业务逻辑
- 将数据库或用户数据保存在未声明的临时容器层

## 验证

- 构建镜像，检查运行用户、启动、健康检查、终止和必要的持久化行为
