# React Rules

## 适用场景

- 修改 React 组件、hook、context、状态或渲染行为

## 必须

- 状态由最接近其真实所有者的层持有，不重复保存可推导数据
- render 保持纯净，副作用放在事件处理或明确的 effect 中
- effect 依赖、清理和异步竞态必须正确处理
- 列表 key 必须稳定表达实体身份

## 建议

- 优先使用组合和局部状态，只有真实共享需求才提升状态或引入 context
- 组件按职责和数据边界拆分，不按代码行数机械拆分
- 复用项目现有表单、数据请求和状态管理方式

## 避免

- 用 effect 同步本可直接推导的状态
- 为简单交互引入新的全局状态库
- 隐式修改 props、共享对象或模块级可变状态

## 验证

- 检查加载、空、错误和成功状态，以及重复交互和卸载后的行为
