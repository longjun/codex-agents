# SwiftUI Rules

## 适用场景

- 修改 SwiftUI View、状态、导航、scene 或预览

## 必须

- 状态由最接近其真实所有者的层持有，数据流保持单向和可追踪
- View body 保持声明式，不执行网络、文件或长期任务等副作用
- 异步任务必须与视图或模型生命周期正确关联，并处理取消
- 导航、sheet 和 alert 状态保持单一来源

## 建议

- 先拆分有独立职责或状态边界的 View，不按行数机械拆分
- 优先使用系统组件、环境和布局能力
- Preview 仅用于快速反馈，不替代真实构建和测试

## 避免

- 重复保存可推导状态
- 在 View 中堆积业务编排和持久化逻辑
- 为简单页面提前引入大型架构框架

## 验证

- 构建实际目标，并检查关键状态、导航、动态字体和深浅色表现
