# Security Rules

## 适用场景

- 修改信任边界、密钥、密码学、权限、不可信输入或敏感数据处理

## 必须

- 明确信任边界、攻击者可控输入、敏感资产和失败影响
- 所有外部输入在对应边界验证，输出按目标上下文正确编码
- 密钥和凭证只来自安全配置，不进入源码、日志、错误或测试夹具
- 使用成熟库和平台原语，不自行设计密码学或认证协议
- 权限遵循最小权限，安全失败默认拒绝
- 日志避免敏感信息，并保留足够的安全审计上下文

## 建议

- 安全修改保持小而可审查，并补充针对原失败路径的测试
- 对依赖、算法和配置使用项目已有安全基线
- 对高风险操作考虑重放、竞态、资源耗尽和滥用限制

## 避免

- 仅依赖客户端校验、字段隐藏或不可猜测 ID
- 吞掉安全相关异常或降低校验强度以让流程通过
- 在没有证据时扩大权限、网络访问或数据暴露范围

## 验证

- 测试允许与拒绝路径、边界输入、日志输出和权限最小化
