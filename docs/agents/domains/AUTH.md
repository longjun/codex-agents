# Authentication and Authorization Rules

## 适用场景

- 修改登录、身份、会话、令牌、角色、权限或资源授权

## 必须

- 同时加载并遵循 `SECURITY.md`
- 认证与授权分开处理；通过认证不代表拥有资源权限
- 授权在服务端、靠近受保护资源的边界执行，默认拒绝
- 会话和令牌必须有明确的签发、过期、撤销、轮换和存储策略
- 资源访问检查主体、动作和具体资源，不只检查客户端传入角色
- 认证失败不泄漏账号是否存在或其他内部状态

## 建议

- 优先使用项目现有、经过验证的认证库和平台能力
- 权限模型保持小而明确，避免重叠角色和隐式继承
- 高风险操作要求重新验证或更强认证上下文

## 避免

- 自行设计密码哈希、令牌格式或密码学协议
- 将长期令牌放入日志、URL 或不安全客户端存储
- 仅隐藏 UI 而不做服务端授权

## 验证

- 覆盖匿名、合法、过期、撤销、跨用户访问和权限提升路径
