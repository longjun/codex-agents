# Filesystem Rules

## 适用场景

- 应用代码修改文件、目录、路径、权限、监听或流式 I/O 行为

## 必须

- 所有外部路径都视为不可信，规范化后检查其是否位于允许边界内
- 写入重要文件时避免留下半成品，必要时使用同目录临时文件和原子替换
- 明确处理文件不存在、权限不足、磁盘已满、并发修改和符号链接
- 及时关闭文件、流、watcher 和临时资源
- 不硬编码用户目录、工作目录或平台路径分隔符

## 建议

- 大文件使用流或有界缓冲，不一次性读入内存
- 保留原有权限和所有权，除非任务明确要求改变
- 临时文件使用平台安全 API，并确保成功和失败路径都能清理

## 避免

- 基于字符串前缀判断路径是否越界
- 先检查再使用而忽略竞态条件
- 静默覆盖用户文件或吞掉部分写入错误

## 验证

- 覆盖不存在、无权限、重复执行、并发和中途失败等相关路径
