# Database Rules

## 适用场景

- 修改 schema、migration、查询、事务、索引或持久化行为

## 必须

- migration 明确前向执行、失败恢复和部署兼容性
- 多步写入在需要原子性时使用事务，并正确传播提交和回滚错误
- 查询必须参数化，不拼接不可信输入
- schema、代码和序列化之间的 null、默认值和时间语义保持一致
- 数据访问层不向业务层泄漏无必要的驱动或 ORM 细节

## 建议

- 索引和查询优化基于真实查询与执行证据
- 大批量操作使用有界批次，避免长事务和无界内存
- 先采用可向后兼容的 expand/contract 迁移方式

## 避免

- 在同一次部署中直接删除仍可能被旧代码使用的字段
- 无依据增加索引、缓存或读写分离
- 隐式 N+1 查询和依赖未声明排序

## 验证

- 测试 migration、回滚或恢复路径、并发冲突和代表性数据量下的关键查询
